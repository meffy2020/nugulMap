# 흡연구역 전용 출시 준비

기준일: 2026-09-07. 이번 사용자 승인 범위는 흡연구역 중심으로 기능을 줄이고 출시 후보를 준비하는 것이다.

## 유지할 동작

로그인 없이 지도·현재 위치·장소 검색·흡연구역 상세·길찾기를 이용한다. 위치 권한 거부 시 검색과 지도 이동을 유지한다. 장소 제보와 오류 신고, 필요한 인증·계정 삭제·지원·개인정보 안내를 유지한다. 기존 장소 리뷰를 노출하는 화면에서는 신고·차단도 유지한다.

## 정리 순서

1. 기존 회귀 테스트를 먼저 실행하고 현재 변경 사항을 보존한다.
2. Android, iOS, 웹/Expo에서 핫플·팝업·추천·방명록의 진입점과 자동 호출을 제거한다. 관련 없는 기존 수정이나 사용자 데이터는 삭제하지 않는다.
3. 서버의 부가 기능 공개 경로와 자동 수집을 기본 비활성화한다. 기존 데이터의 계정 삭제·보관기간 처리와 스키마는 유지한다.
4. 출시 검사를 흡연구역 조회·검색·상세·정책·지원 중심으로 바꾸고, 권한 안내와 스토어 원고를 실제 동작에 맞춘다.
5. 플랫폼별 테스트·정적 검사·빌드와 운영 API 읽기 검증을 실행한다. 서명·실기기·스토어 계정 증거가 없으면 출시 완료로 표시하지 않는다.

## 시작 시 확인한 기준선

- 공통 Python 출시 검사 테스트: 85개 통과.
- Java 21 백엔드 테스트: Gradle 성공(기존 산출물 UP-TO-DATE). 변경 후 새 실행으로 다시 확인한다.
- 네이티브 정적 검사: PASS 47 / MANUAL 9 / FAIL 3. Android 서명 설정과 AAB가 없고, 위치 권한 검사는 현재 구현을 반영하지 못하고 있다.
- iOS 서명 Team과 실기기 OAuth·지도 확인, 스토어 입력은 별도 증거가 필요하다.

## 출시 승인 기준

흡연구역 외 화면/자동 요청 없음, 핵심 경로의 오류·빈 결과·권한 거부 처리, 테스트와 출시 빌드, 운영 API/정책 URL 정상, 서명된 설치본에서 지도·로그인·제보·신고·계정 삭제 검증, 실제 스토어 입력과 지원 대응 준비가 모두 확인되어야 공개 출시 가능으로 판정한다.

로컬 준비와 운영 반영은 구분한다. 이번 작업에서 운영 배포·스토어 제출·계정/데이터 삭제는 수행하지 않는다. 배포 후보와 검증 결과를 먼저 완성한다.

## 사용자 추가 입력 없이 진행하는 후속 검증

실제 MySQL 8의 격리 DB에 스키마와 마이그레이션을 두 번 적용하고, 테스트 자료 격리 및
운영 프로필의 문의·리뷰·신고·차단·계정 삭제를 확인한다. 누락된 필수 DB 컬럼으로 기동을
거부하는지도 확인해 스키마 검사가 비활성화되는 설정 충돌을 회귀 테스트로 고정한다.
Android는 실제 제출 키와 분리한 테스트 서명 릴리즈 및 16KB 호환성을 검사하고,
iOS는 서명 없는 기기용 아카이브와 iPad를 검증한다. 데이터 원본 대조 결과는 별도 자료로
보관하고 운영 데이터에는 쓰지 않는다.
